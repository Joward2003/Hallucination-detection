# 已选架构：证据约束型有界 Agentic RAG

> 状态：编码基线  
> 日期：2026-09-16  
> 详细骨架：[system_skeleton.md](system_skeleton.md)

## 1. 产品定位

本系统是中国农业银行、学院团队共同推进的金融信贷分析报告 AI 复核工作台。系统不替代银行人员作出信贷判断，而是将 AI 报告拆解为 Parent–Child Fact，建立“结论—证据—推理—风险”链路，帮助业务人员识别无依据、错配、过度推断和风险遗漏。

复核分为四个维度：

1. 证据存在性：是否能定位到原始材料及具体位置。
2. 证据支持性：证据是否真正支持 Child Fact，而不只是语义相关。
3. 推理完整性：证据到结论之间是否存在跳跃、计算错误或表述过强。
4. 风险完整性：是否遗漏足以改变结论的重要风险或反向证据。

统一问题标签：`证据不足`、`引用错配`、`表述过强`、`推理跳跃`、`风险遗漏`。

最终核验状态只允许为：`SUPPORTED`、`CONTRADICTED`、`INSUFFICIENT_EVIDENCE`。其中“没有检索到足够证据”不得直接转译为事实错误。

## 2. 架构决策

采用“方案一主干 + 方案二增强”，并以 Parent–Child Fact Representation 作为事实层基础：

- 主干为显式 LangGraph 状态机，节点、条件边、重试次数和终止条件由代码控制。
- Parent–Child 提取、证据规划、证据关系判断由受限 Agent 完成。
- 检索、计算、规则执行、权限检查、状态持久化使用确定性组件。
- Critic Agent 只在高风险、低置信、证据冲突或规则要求时触发。
- Critic 独立取证；初判与 Critic 冲突时进入人工复核。
- 人工节点采用风险分层，不要求每一步审批。

该架构是“多智能体分工 + 有界工作流”，不是自由对话式 Supervisor/Swarm。新架构不以兼容旧 State、旧节点或旧 Atomic Fact 接口为目标；冲突实现可直接替换或删除。

## 3. 主链路

```text
报告接入
  → Parent–Child Fact Extraction
  → 公司识别
  → Child Fact 分类与证据需求规划
  → 文本/表格/混合检索（支持证据 + 反向证据）
  → Evidence Grading 与 Rerank
  → 证据不足时有界 Query Rewrite
  → 确定性数值校验
  → 业务规则检查
  → Child + Parent + Evidence 初步验证
  → 风险门控
      ├─ 普通场景：形成结果
      ├─ 高风险/不确定：Critic 独立复核
      └─ 冲突/强制条件：人工确认
  → 结构化复核报告
  → 标注和坏案例回流
```

## 4. 组件职责

| 组件 | 核心职责 | 是否允许自主循环 |
|---|---|---|
| Parent–Child Extractor | 保留原始 Parent 语境，并拆出可检索的 Child Fact | 否 |
| Evidence Planner | 识别指标、期间、主体、证据类型及反向证据需求 | 否 |
| Retrieval Workers | 执行文本、表格和混合检索 | 否 |
| Evidence Grader | 标注支持、部分支持、无关、反向证据并排序 | 否 |
| Query Rewriter | 证据不足时改写检索式 | 最多执行配置次数 |
| Numeric Validator | 校验金额、比例、同比、单位和期间 | 否；禁止 LLM 代算 |
| Rule Engine | 执行版本化业务规则 | 否 |
| Fact Verifier | 同时使用 Child、Parent 和外部 Evidence，判断支持关系、推理强度和风险完整性 | 否 |
| Risk Gate | 决定结束、Critic 或人工介入 | 否；策略驱动 |
| Critic Agent | 独立取证并复核高风险 Child Fact | 否 |
| Human Review | 处理歧义、冲突、高风险和低置信结果 | 人工决策 |
| Aggregator | 汇总 Child 级结果，不重新发明结论 | 否 |

## 5. 强制边界

- 系统输出是复核意见，不是授信审批或信贷决策。
- 任一 `SUPPORTED` 结论必须关联来源、位置和外部证据片段。
- Parent 只用于恢复原始语境，不能作为外部 Evidence 参与支持或反驳。
- “未召回证据”只能判为证据不足，不能自动判定事实为假。
- 证据相关不等于证据支持，必须输出关系等级。
- 数值计算结果必须来自确定性校验器，并保留输入和公式。
- 高风险 Child 可配置为无条件人工确认。
- 所有模型调用、规则版本、证据快照和人工操作必须可审计。
- Agent 不得绕过数据权限、规则引擎、风险门控或人工节点。
- 外部模型不得接收未经批准的敏感银行数据。

## 6. 对当前项目的处理

### 可复用资产

- OCR JSON 接入思路。
- 文本/表格分库和 Chroma 资产。
- 文本、表格、混合检索能力。

以上仅指数据或能力资产可复用，不代表保留旧接口或旧语义。

### 重写

- 将检索工具改为无 Agent 依赖的服务接口，由 Graph 调用。
- 重新设计 Parent–Child Fact Extraction，不在旧 Atomic Fact Extractor 上简单加字段。
- 将公司选择改为规则/权限过滤优先、LLM 兜底的结构化路由。
- 将 rerank、证据分级、数值校验、规则校验拆成独立节点。
- 将运行配置、密钥、模型选择和阈值移出源码。

### 删除或替换

- 替换现有 `initialize_agent` 自由 ReAct 路由。
- 替换单一 `hallucination: true/false` 输出为三态核验结果。
- 替换依赖正则抽取最后一个数字的批量答案逻辑。
- 替换明文 API Key。
- 删除与旧 Atomic Fact、旧 State 和旧字段强绑定且无新架构依赖的代码。

## 7. 为什么不采用纯 Atomic Fact 和全量双 Agent

纯 Atomic Fact 有利于细粒度检索，但过度拆分会破坏主体、时间、数字单位、限定条件、联合关系和因果关系。Child 负责检索和逐事实核验，Parent 保留原始语境；Fact Verification 必须同时输入 Child、Parent 和外部 Evidence。

例如“海外市场拓展和新产品放量共同推动收入增长”不能拆成两个分别成立的单因素因果事实。Parent 也不能被当作 Evidence，否则会形成“报告自证报告”的循环论证。

全量双 Agent 或 Supervisor/Swarm 的取舍：

- 相同模型和相同证据可能产生相关性错误，Agent 数量增加不等于准确率增加。
- 全量双跑会显著增加成本和延迟，因此只对高风险 Child 启用 Critic。
- 当前任务阶段和终止条件较明确，不需要 Supervisor 动态发明执行路径。
- 自由 handoff 难以回归测试，不适合责任边界严格的金融复核。

## 8. 暂未稳定的决策

- **待定**：银行侧部署方式、网络边界、数据分级和允许使用的模型服务。
- **待定**：生产向量库继续使用 Chroma，还是迁移到支持更强并发和权限隔离的存储。
- **待定**：20 多条业务规则的正式定义、优先级、冲突处理和版本管理流程。
- **待定**：模型置信度的校准方法；不得直接把模型自报概率当成真实置信度。
- **待定**：约 90% 核心准确率的样本范围、指标公式和测试集隔离口径。
- **待验证**：当前 NVIDIA 兼容接口对结构化输出、工具调用和重试语义的支持程度。
